# START HERE — how to use this prompt pack on the other PC

This folder is a complete, self-contained "recipe" for rebuilding the **Expense & Reimbursement Agent** with
any coding AI agent (OpenAI Codex, Amazon Q Developer, Claude Code, Cursor, Copilot agent mode, ...).
It contains **text only** (no binaries), so it can be typed, pasted or transferred through any text channel.

## Two ways to feed it

**A. Agent can read files in the workspace (Codex CLI, Q Developer CLI, Claude Code, IDE agents).**
1. Create an empty project folder, e.g. `expense-agent/`, and copy this `rebuild_prompt/` folder into it.
2. Open the agent in that folder and paste the contents of `MASTER_PROMPT.md` as the first message.
3. When it asks for the LLM API key, put it in `expense-agent/.env` yourself (see below); do not paste it in chat.

**B. Chat-only agent (cannot read your disk).**
Paste the files in the order of the table above, one message each, saying "Read and remember this file; do
not act yet" for every file except the last; then paste `MASTER_PROMPT.md` last (or first, then the rest).
Because the appendix is large, paste `A1`..`A5` as separate messages. If the chat has a size limit, split a
file at a `### FILE:` boundary — never in the middle of a file.

## Prerequisites on the other PC

* **Python 3.11 or newer** (built with 3.14.7). Check: `python3 --version` (macOS/Linux) or `py --version` (Windows).
* `pip`, and internet access to PyPI **for installation** (the finished app also needs internet for live LLM calls).
* **One LLM API key** with a **vision-capable** model that supports tool/structured output:
  * Anthropic (default): `ANTHROPIC_API_KEY`, model `anthropic:claude-sonnet-5-5`; or
  * Google AI Studio (free tier works but is rate limited): `GOOGLE_API_KEY`, model e.g. `google:gemini-3.8-flash`; or
  * OpenAI/others supported by Pydantic AI (`openai:<vision model>` + `OPENAI_API_KEY`).
  Put the key in a file named `.env` at the project root: `ANTHROPIC_API_KEY=...` plus `LLM_MODEL=...`.
  **Model names change over time** — if a model name is rejected (HTTP 404), use a current vision-capable model
  name from your provider's console; nothing else in the project depends on a specific model.
* A browser (Chrome/Edge/Firefox/Safari) to use the UI.
* Git is optional; the project does not require it.

## What does NOT carry over (and how the pack handles it)

| Not carried | Consequence | Handling |
|---|---|---|
| `data/cache/**` (cached AI results: ~400 KB of JSON) | The first run must call the LLM | Stage 7 "warm-up run" regenerates all caches (until then 8 API tests are skipped with a message) (about 50 LLM calls; a few US cents on a paid key) |
| `data/synthetic/receipts/*` (images/PDFs) | none | Regenerated by `tools/generate_receipts.py` (deterministic apart from PDF timestamps and installed fonts) |
| `docs/screenshots/*.jpg` (5 images), the `.pptx` | README images would be broken; the deck has grey placeholders | Capture the five screenshots from the running app with the exact names in `09_...` section 4, then `python tools/make_deck.py` |
| `.env` (your key) | none | You create it |
| Git history | none | Not needed |

## Expected effort and cost

* Agent build time: 20–60 minutes depending on the agent (most of it is writing ~9,000 lines of verbatim code, tests and documents).
* LLM cost of the warm-up run and demo: small (about 50 calls for the warm-up). Free-tier keys may hit daily
  quotas (see troubleshooting) — the Anthropic key is the smoothest path.

## Tips for weaker agents

* Tell the agent explicitly: "Copy the code blocks exactly; the tests depend on exact behaviour."
* If the agent wants to "tidy" or "simplify" files, stop it; the appendix is final.
* After each stage ask it to paste the verification output (not a summary) so you can check it.
* If it cannot hold the whole appendix in context, build stage by stage: for each stage, give it only the
  relevant `### FILE:` blocks (the stage tables in `08_...` list exactly which files belong to each stage).
