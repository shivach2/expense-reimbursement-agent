## Windows/PowerShell Specifics

| Task | Windows Command |
|---|---|
| Create venv | `py -m venv .venv` |
| Activate venv | `.venv\Scripts\Activate.ps1` |
| Python path | `.venv\Scripts\python.exe` (abbreviated `PY` in docs) |
| Set env var for one run | `$env:CLAIM_TODAY="2026-10-12"; .venv\Scripts\python.exe -m uvicorn ...` |
| Multi-var one run | `$env:PYDANTIC_AI_NO_BANNER="1"; $env:CLAIM_TODAY="2026-10-12"` |
| Find process on port | `Get-NetTCPConnection -LocalPort 8000` |
| mkdir equivalent | `New-Item -ItemType Directory -Force -Path "path"` or `mkdir -p` in pwsh 7+ |
| Run from backend/ | `cd backend` (then commands run relative to there); or add `--app-dir backend` |
| Grep equivalent | `Select-String -Path file -Pattern "pattern"` or `findstr /i "pattern" file` |
| Font for receipt images | Falls back to Pillow's default (no Courier New/Menlo needed, just looks plainer) |
| `lsof` not available | Use Task Manager or `Get-NetTCPConnection` |
| `ruff` location after install | `.venv\Scripts\ruff.exe` (or just `ruff` if venv is activated) |

### Key path note
All paths inside the code are computed from `Path(__file__).resolve().parents[N]` — they work regardless of the current directory as long as:
- Tests are run from `backend/` (set by `pytest.ini` → `pythonpath = .`)
- The server is started from `backend/` (or with `--app-dir backend`)
- `get_settings()` anchors to `config.py`'s location two levels up to reach the project root

## Important Rules for the Coding Agent

1. **Verbatim copy only.** Every `### FILE:` block in A1–A5 must be created exactly as written. Do not rename, refactor, "modernize", or fix anything. The tests were written against these exact files.
2. **Appendix beats specs.** If any spec file (01–09) says something different from an A1–A5 file, the appendix file wins; note the discrepancy in the final report.
3. **No secrets.** Never write any API key value into any file. Only `.env` (which is git-ignored) holds the key. The human supplies it.
4. **No extra dependencies.** Do not add packages beyond `backend/requirements.txt` and `backend/requirements-dev.txt`.
5. **Pin pydantic-ai explicitly.** Run `pip install "pydantic-ai==2.54.0"` before `pip install -r backend/requirements-dev.txt` to ensure the correct version.
6. **Commit `data/synthetic/` and `data/cache/`.** These are synthetic; the CI and offline demo depend on them. Do NOT git-ignore them.
7. **Do not start the next stage until the current one passes.** Each stage has a verification command and expected output.
8. **Stage 7 requires a real API key.** The human must create `.env` with their key before Stage 7. The agent should not block on this — complete all other stages first.
